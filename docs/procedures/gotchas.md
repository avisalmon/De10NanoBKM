# Gotchas: the traps, and how each one is known

Each row is a trap on the way from a design to a DE10-Nano running it, with its fix and **how we know**: tested
here with the tools (Icarus Verilog 12 and Quartus Prime Lite 17.1, on small test designs), read in Terasic's user
manual ("manual p.N", the PDF page), seen on the computer this repo was written on, or [community] advice not yet
seen here. The board's facts and their sources are in [the reference](../de10nano_reference.md).

Other pages may point at a row by its number, so do not renumber: add new rows at the end, and when a row turns
out wrong, say so in it rather than deleting it.

| # | Gotcha | Fix | How we know |
|---|---|---|---|
| 1 | Programming at `@1`, the DE10-Lite habit. On the DE10-Nano the chain has two devices: `@1` is the HPS (the ARM side), and the FPGA is `@2` | `fpga.py program` finds the FPGA (`5CSEBA6`) by name. By hand: `quartus_pgm -m jtag -c "DE-SoC [USB-1]" -o "p;output_files/<name>.sof@2"`. A test fails if a doc shows any other position | Two devices: manual p.13. The order: two community guides. Not yet seen on a board here |
| 2 | The USB cable in the wrong port. The board has two Mini-B ports (the USB-Blaster II, and a UART to the HPS) and a Micro-AB OTG port; only one of them programs the FPGA | The **USB-Blaster II** Mini-B port (J13 [community]). `fpga.py jtag` then lists `DE-SoC` | manual p.8-9 |
| 3 | The wrong Windows driver: Quartus ships two, `drivers\usb-blaster` (the older USB-Blaster) and `drivers\usb-blaster-ii` | The board's built-in blaster is a USB-Blaster **II**: point Device Manager at `<Quartus>\drivers\usb-blaster-ii` ([install_tools.md](install_tools.md#4-the-usb-blaster-ii-driver)) | Both folders seen in a 17.1 install; Intel's instructions (archived) |
| 4 | Quartus Prime Lite installed, but it cannot compile for the DE10-Nano: the Cyclone V **device package** was never installed | `fpga.py doctor` asks every Quartus it finds for its families (`[MISS] Quartus with Cyclone V`). Add the package: [install_tools.md](install_tools.md), section 3b | Seen on the computer this repo was written on: Quartus 17.1 with MAX 10 only |
| 5 | The microSD card's Linux stops booting after SW10 was changed | Power off, set SW10 back to the factory FPPx32 (`MSEL[4:0] = 01010`: switches 1 to 5 ON, OFF, ON, OFF, ON), power on. Programming over JTAG should not need SW10 changed at all | manual p.11-12. "JTAG works whatever SW10 says": [community], inferred from the manual |
| 6 | The design is gone after a power-off | Normal: a `.sof` lives only in the FPGA's memory. Program it again. Keeping a design means the EPCS64 flash through the Serial Flash Loader, not covered yet ([roadmap](../blueprint_roadmap.md)) | manual p.12-13 |
| 7 | A misspelt pin name in the `.qsf` still compiles: Quartus only warns `Warning (15706): Node "ledx[0]" is assigned to location or region, but does not exist in design`, and gives the real port a pin of its own choosing (`Critical Warning (169085): No exact pin location assignment(s) ...`) | `fpga.py build` shows both lines. Make the `.qsf` name and the port name identical, character for character. Never program a build that printed 169085 | Tested with Quartus 17.1 |
| 8 | A latch passes simulation: an `always_comb` that leaves an output without a value on some path. Icarus 12 accepts it without a word; Quartus 17.1 stops with `Error (10166)`. In an `always @(*)` the same latch is only `Warning (10240)` | Write combinational logic in `always_comb` (so Quartus refuses a latch), and give every output a default value at the top of the block | Tested with Icarus 12 and Quartus 17.1 |
| 9 | A misspelt name in a port connection silently becomes a new 1-bit wire (an implicit net). Icarus only warns `implicit definition of wire`; Quartus warns (10236), and the output it was meant to drive is `stuck at GND` | `` `default_nettype none `` at the top of every design file and `` `default_nettype wire `` at the end, as the template does: both tools then refuse the typo | Tested with Icarus 12 and Quartus 17.1 |
| 10 | Icarus prints `sorry:` and carries on: it supports that construct only in part (for a `unique case` the `unique` is ignored), and still exits 0. Concurrent assertions (`assert property ...`) are a syntax error in Icarus 12 | Read the warnings under a `PASS`. Write the plain form: a `case` with a `default`, and checks as `if (...) $display("FAIL: ...")` in the testbench | Tested with Icarus 12 |
| 11 | No `.sdc`, or the `.qsf`'s `SDC_FILE` names the wrong file: `Critical Warning (332012): Synopsys Design Constraints File file not found`, and timing "fails" against a clock Quartus made up | Keep the project's `.sdc` (the template's defines the 50 MHz clock) and its `SDC_FILE` line; `fpga.py new` renames both | Tested with Quartus 17.1 |
| 12 | Errors about long paths, or files locked while Quartus writes them: the project is deep in folders, or inside OneDrive (often the case for `Documents` on Windows) | Keep the work in a short folder outside OneDrive, like `C:\fpga\my-fpga` | [community] advice; not seen here |
| 13 | The headers are **3.3 V**: a 5 V signal (a 5 V Arduino shield's outputs, a 5 V sensor) on an FPGA pin can damage the FPGA | A level shifter. Wire and unwire only with the power off. Before wiring, write down which pins, which direction and which voltage ([de10nano-board](../../.claude/skills/de10nano-board/SKILL.md)) | The 3.3 V I/O standard: Terasic's golden-top `.qsf`. "Not 5 V tolerant": this repo's standing assumption, [unverified] |
| 14 | A testbench that prints nothing, or stops before its checks, looks like a pass to someone skimming the output | `fpga.py sim` counts a pass only with a line starting `PASS` and no `FAIL` anywhere. Every testbench ends with a `PASS` or `FAIL:` line and has a time-out block | Built into `fpga.py`, and a test (`says-nothing`) holds it to that |
| 15 | RocketBoards' DE10-Nano wiki gives the FPGA as `5CSEMA6U23I7N` and the flash as EPCS128 | Trust Terasic: `5CSEBA6U23I7` and the EPCS64 ([the reference](../de10nano_reference.md)) | Checked against the manual and the golden-top `.qsf`, 2026-10 |
| 16 | Downloading Quartus or a device package with a script (curl, wget) gets `403` "Access Denied" | Download in a browser (sometimes signed in), then check the file's SHA1 ([install_tools.md](install_tools.md), section 3b) | Seen 2026-10, with and without a browser's user agent |
| 17 | A `403 Forbidden` that is not the site's at all: a company web filter blocks the download (`winget`: `0x80190193 : Forbidden (403)`) | Open the address in a browser and read the page: "Blocked by ..." is your network, not the site. Use another network, or ask IT to allow it | Seen 2026-10: the Icarus Verilog installer's site, blocked by a corporate filter |
| 18 | An old `QUARTUS_ROOTDIR` environment variable, left behind by a Quartus that was uninstalled | Harmless to `fpga.py`, which skips any folder without `quartus_sh`. Remove it if another tool gets confused | Seen on the computer this repo was written on |
| 19 | A slide switch is not debounced, and a button reads **0 while pressed**: logic written for 1 = pressed does the opposite, and a counter stepped by a switch counts several times per flip | Invert once, at the top level (the template: `wire reset = !key_sync[0];`). Pass every input through a two-flip-flop synchronizer, and debounce a switch before counting its changes | manual p.23-25; the template's `de10nano_top.sv` |

Something new went wrong and was solved: add a row here, a line to the [lessons log](../lessons_log.md), and the
fix to the skill that covers it (CLAUDE.md rule 10).
